# M3-06.2 — Dynamic Dashboard Plan

## Status

Planning

---

## Purpose

Connect the Dashboard to the Adventure Brain so the application can intelligently determine what deserves the user's attention today.

This milestone introduces the first user-visible intelligence powered by Adventure Brain while keeping responsibilities clearly separated between decision-making and presentation.

---

## Objectives

- Display Adventure Brain insights on the Dashboard.
- Surface a single Daily Focus.
- Display Adventure Phase.
- Support graceful fallback behavior.
- Preserve existing dashboard functionality.
- Keep UI rendering separate from Adventure Brain evaluation.

## Out of Scope

- Living Campfire
- Family Readiness intelligence
- Packing intelligence
- Weather prioritization improvements beyond existing Adventure Brain support

---

## Architectural Decisions

### Approved

- [x] Dashboard requests one evaluated Adventure Brain state.
- [x] Adventure Brain owns all decision-making.
- [x] Dashboard owns presentation only.
- [x] Dashboard renders from a single immutable evaluation result.
- [x] Adventure Brain state is passed into `dashboardMarkup()` from `drawHome()`.
- [x] The Dashboard does not run Adventure Brain evaluation itself.

### Guiding Principle

> **Think once. Render everywhere.**

---

## Notes

Adventure Brain remains responsible for determining _what_ is important.

The Dashboard remains responsible for deciding _how_ it is displayed.

---

## Future Expansion

This milestone intentionally introduces only the first Adventure Brain
dashboard integration.

Future milestones will extend the Dashboard with richer context,
additional signals, and deeper personalization while preserving the
same separation of responsibilities.
